# AI 방식 작은 MAC 계산기

## 목적과 실행

이 프로젝트는 필터와 입력 패턴의 같은 위치 값을 곱해 누적하는 MAC을 작은 Python 프로그램으로 흉내 냅니다. 원본 `data.json`이 제공되지 않아 요청에 따라 학습용 합성 데이터를 만들었고, 실제 데이터가 오면 `data.json`만 교체하면 됩니다.

```powershell
python main.py
python -m unittest discover -s . -p "test_*.py"
```

메뉴 1은 3×3 직접 입력, 메뉴 2는 JSON 자동 분석, 메뉴 3은 홀수 크기 Cross/X 자동 생성입니다.

## 모드 1: 직접 입력

각 행에 숫자 3개를 입력하고, 행 개수·열 개수·문자·NaN·무한대를 검사합니다. 오류가 나면 안내 후 행렬 전체를 다시 입력합니다. `mac_2d`는 입력→같은 위치 곱셈→누적→점수 반환 순서로 동작합니다. A/B 점수, 10회 평균 MAC 시간(ms), 최종 판정을 한 결과 구역에 출력합니다.

모드 1의 동점 표시는 요구사항에 맞춰 `판정 불가`입니다. `EPSILON=1e-9` 이내의 차이를 동점으로 보는 이유는 부동소수점 계산의 아주 작은 오차를 승패로 오해하지 않기 위해서입니다.

## 모드 2: JSON 자동 분석

`size_N_번호` 키에서 N을 추출해 `filters[size_N]`를 선택하고, `+`/`cross`/`Cross`는 Cross, `x`/`X`는 X로 정규화합니다. `normalize_label`을 별도 함수로 둔 이유는 입력 표준화와 판정을 분리해 새 라벨을 한 곳에서 확장하고 재사용하기 위해서입니다.

점수가 높을수록 필터와 패턴의 같은 위치가 많이 일치하므로 유사도가 높다고 해석합니다. 최고 점수가 EPSILON 안에서 동점이면 모드 2는 `UNDECIDED`로 표시하고 정답과 다르므로 FAIL로 집계합니다. 실패 항목은 key와 이유 목록으로 출력합니다.

모드 2는 다음 성능 표도 출력합니다.

```text
크기 | 평균 ms(10회) | N² 연산 수
3 | 실행 시 측정 | 9
5 | 실행 시 측정 | 25
13 | 실행 시 측정 | 169
25 | 실행 시 측정 | 625
```

입력 대기와 출력은 측정하지 않고 MAC 함수 호출만 `time.perf_counter()`로 10회 측정합니다. 시간복잡도는 N×N 위치를 방문하므로 O(N²)입니다. 크기가 3에서 5로 증가하면 연산 수가 9에서 25로 증가하는 것처럼 크기의 제곱에 비례합니다.

## 결과 리포트

현재 합성 데이터의 실행 결과는 `evidence/test-run.txt`에 기록합니다. 기본 테스트는 2D/1D 점수 일치, 모드별 동점 문구, JSON 분석, 패턴 생성, NaN 거부, 크기별 N² 표, 모드 1 평균 시간 보고를 확인합니다.

실패 원인 분석 기준은 다음과 같습니다.

1. 행렬 크기가 다르면 MAC을 시작하지 않습니다.
2. 문자가 들어오면 숫자 변환 단계에서 실패합니다.
3. NaN과 무한대는 결과 오염을 막기 위해 거부합니다.
4. 패턴 키가 `size_N_번호` 형식이 아니면 해당 사례만 FAIL입니다.
5. 해당 크기의 필터가 없으면 해당 사례만 FAIL입니다.
6. 지원하지 않는 라벨은 필터 점수에서 제외됩니다.
7. 지원 필터가 하나도 없으면 FAIL 이유를 남깁니다.
8. 최고 점수가 동점이면 모드 2에서 UNDECIDED입니다.
9. 예상 라벨과 예측 라벨이 다르면 FAIL입니다.
10. JSON 파일 자체가 없거나 문법이 틀리면 분석을 시작할 수 없습니다.
11. 1000×1000은 1,000,000개 위치라 Python 반복 비용이 커집니다.
12. 실행 시간은 CPU·Python 버전·다른 프로세스에 따라 달라집니다.

## 큰 입력·CPU/NPU 분석

1000×1000은 O(N²)이며 모든 값을 메모리에 둔 뒤 직렬 Python 반복으로 처리하면 CPU 계산과 메모리 접근이 병목입니다. 최적화 우선순위는 ① 행 단위 생성으로 메모리 피크를 줄이고, ② 실제 측정으로 병목을 확인하고, ③ NumPy 벡터화나 C 확장으로 반복 비용을 줄이고, ④ 필요할 때 병렬 처리를 검토하는 순서입니다. 행 단위 처리가 항상 더 빠르다고 가정하지 않습니다.

CPU는 소수의 코어가 범용 명령을 순차 처리하므로 Python 루프 오버헤드가 큽니다. NPU는 많은 MAC을 병렬 처리할 수 있지만 데이터 이동, 버퍼 배치, 메모리 대역폭이 병목이 될 수 있습니다. 이 프로젝트에서는 실제 NPU를 실행하지 않았으므로 이 부분은 이론 비교입니다.

## 확장 절차

새 라벨을 추가할 때는 `normalize_label` 매핑 추가→`analyze_json`의 점수·동점 출력 확인→해당 라벨의 단위 테스트 추가→README의 지원 라벨과 결과 표 갱신 순서로 진행합니다. 저장 포맷이나 필드가 바뀌면 `load_data`, JSON 검증, 테스트, 예시 데이터를 함께 수정합니다.

## 파일 구조

- `main.py`: 검증, 2D/1D MAC, 동점 판정, JSON 분석, 성능표, 입력 재시도
- `data.json`: 학습용 필터·패턴 데이터
- `test_main.py`: 핵심 기능 자동 테스트
- `evidence/test-run.txt`: 실제 테스트 결과
